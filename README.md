# WTStat all

官网 Replay 增量统计工具，Windows 下可单独安装和运行，无需原 `WTStat` 项目。把本仓库放在任意目录，双击 `start.bat`，访问 <http://127.0.0.1:8767>。首次运行需要 Python 3 和网络来安装 `requirements.txt` 中的依赖；之后使用本目录的 `.venv`。Replay 解析器、载具表和字体均随本仓库提供。普通 WTStat 如已安装，可同时在 8766 端口运行。

采集窗口标题显示 `WTStat ALL - Replay Sampler - Port 8767`。关闭采集窗口会停止采集，但已保存的样本保留；重新运行本目录的 `start.bat` 后，在网页点击“开始采集”即可继续。

## 随仓库提供的运行文件

`bin/wtstat_results.exe` 是 Windows Replay 解析器；对应源码和 AGPL 许可位于 `vendor/wrpl-inspector/`。`data/wiki_vehicles.csv` 是随仓库提供的 Wiki 载具资料快照，`static/fonts/` 包含界面使用的 Wiki 字体。运行时只读取本目录的这些文件，不访问其他项目文件夹。如需自行重建解析器，安装 Go 后在 `vendor/wrpl-inspector` 目录运行 `go build -o ../../bin/wtstat_results.exe ./cmd/wtstat_results`。

## 登录与运行

官网全站对局列表需要 `identity_sid`。把本目录的 `config.local.example.json` 复制成 `config.local.json`，并填入自己的 Cookie。数据库、Replay 缓存和 Cookie 配置都在本目录，Cookie 不写入日志和 Git。打开网页后设置并行数、保留文件数和采集模式（全部／空战历史／陆战历史，默认全部），点击“保存设置”后再“开始采集”；“停止采集”会停止派发新对局，当前下载会完成。切换采集模式须先停止，保存后扫描页号重置为 1，只下载所选模式的结算段；已保存样本不删除。设置和扫描页号在重启后保留，开关重启后默认关闭。

官网接口在不指定玩家时可分页返回全站列表。程序只请求 `randomBattle` 的历史模式，跳过海战及其他类型。每局先按列表的 `partsCount` 下载候选结算 `.wrpl` 分段；该编号在尚未完成的对局中可能仍指向过程分段。若返回 404，会再试前一段；若两段均为 404，或下载的分段没有玩家结算数据，就标记为“待结算”。至少 15 分钟后补试；每次读取新列表页之前，优先并行补试最多 15 场已到时间的待结算对局，按上次尝试时间从早到晚处理。对缺结算数据的对局，仅探测最多 8 个后续分段的响应头，下载最新候选分段。官网请求使用间隔、有限重试与限流处理；遇到 429 停止扫描。每处理 20 页重新检查最新一页，再继续保存的页号，重复 Session 不会重复统计。

数据库位于 `data/wtstat_all.sqlite3`。`samples` 保存逐玩家数据、非自动小队队友的科技树国家及小队标识；统计时按小队去重。新处理的对局还保存队伍编号、每名玩家的配置载具和结算战绩（对空击杀、地面击杀、死亡、助攻、得分及其他解析器提供的字段），只使用已下载的结算末段，不增加 Replay 下载。配置载具不证明实际出击；旧样本此前未保存的字段显示 N/A。旧版的 `histogram` 表仍保留，但新的小队统计直接从 `samples` 计算。默认按对局开始时间保留最近 100 场 Replay 的结算文件；网页可改为 0–1000 场。旧版默认值 10 在升级时一次性改为 100，其他自定义值保留；已经删除的 Replay 文件不会自动重下。删除 Replay 文件不影响已入库的统计和玩家详情。最近处理列表显示 100 场，点击某局可按队伍查看已保存玩家数据，每列表头可独立排序；旧样本如仍保留本地结算段，打开详情时会从本地补读队伍编号。载具特殊国别标志使用 WTStat 字体显示。CSV 导出队伍编号、配置载具、结算战绩 JSON，以及对局开始时间、地图、原始玩家数、结算段编号和原处理时间。停止采集后可在另一台电脑的 WTStat all 页面点击“导入 CSV”；同一 Session ID 只保留一条对局，同一 Session ID＋玩家 UID 只保留一条玩家样本，重复导入不会重复计数。导入在一个事务内完成，遇到格式错误会整批回滚。旧版 CSV 也可导入，但未导出的对局时间和原始玩家数无法从 CSV 恢复，因此时间筛选及部分高权重分类可能缺失。迁移运行只需复制本仓库目录；目标电脑重新安装 Python 依赖并在本目录配置自己的 identity_sid。停止采集并等待当前下载结束后，可点击“清除所有数据”删除本工具的对局、样本、统计和 Replay 文件，扫描位置重置到第一页；并行数、保留数量和 Cookie 配置保留。此操作无法撤销。

页面显示已保存样本对应对局的最早和最晚开始时间。时区下拉框列出具名地点及固定 UTC 偏移，包括“北京 · UTC+08:00”；实行夏令时的地区需选择对应季节。选择截止时间并点击“删除此前样本”，输入会按所选时区换算为 UTC，删除严格早于该时间的玩家样本并重算统计；没有可靠对局时间的样本不受影响。此操作需要先停止采集，且不会删除已处理对局记录或 Replay 文件，因此后续扫描不会自动重新加入已删除的样本。

## 统计口径

一个非自动小队在一局中计一个样本；单排玩家各计一个，自动小队视为单排。筛选框中的“权重”是小队成员最高阵容 BR；“对局权重”是该局所有玩家最高阵容 BR 的最大值。国家指配置载具的唯一科技树国家；无法可靠确定时为空。国家“不限”汇总所有完整小队，可再按队友数量筛选。选定玩家国家后，必须选择队友数量并填齐队友 1/2/3 国家；只匹配人数与国籍多重集合完全相同的队伍，队友顺序不限。例如“日本、日本、美国、美国”只在日本＋（日本、美国、美国）或美国＋（日本、日本、美国）条件下命中一次；只选日本单排不会命中。无小队标识的旧样本按同局、相同完整国籍组合与权重分组，并仅在成员行数能组成完整队伍时纳入；无法可靠还原的记录不计。任一玩家阵容权重无法确定导致对局权重为 N/A 时，该局玩家记录仍保留，但不进入分布与汇总。

每个组队权重分别统计对局权重的样本量、平均值、中位数、**总体标准差**、最大值、最小值；最大值和最小值只在上方统计卡片展示。通常，大班长率的对局权重差为 0，小班长率为 0.3/0.4，班长率是两者之和；小壮丁率为 0.6/0.7，大壮丁率为 1.0。距离模式权重上限不足 1.0 时（空战 14.0/14.3/14.7，陆战 12.3/12.7/13.0），改按本局**最低组队权重**判定：组队权重比最低权重高至少 1.0 为大班长，高 0.6/0.7 为小班长，高 0.3/0.4 为小壮丁，相同为大壮丁。使用实际出现的最高–最低组队权重区间，不预设区间宽度为 1.0。例如 14.7 组队在 14.7–14.7 对局、14.3 组队在 14.7–14.3 对局均为大壮丁；14.3 在 14.7–13.7 对局为小班长。最低权重由数据库中同局所有玩家的**组队权重**重算，低权重玩家若与高权重玩家组队，按该队的最高权重计；不需要重新下载旧 Replay。若该局玩家记录或组队权重不完整，不能可靠分类。分母是该筛选下对局权重已知的小队/单排样本数，未能分类或四类之外的差值仍计入分母。历史陆战只显示 1.0–13.0，历史空战只显示 1.0–14.7，合法小数部分为 .0/.3/.7。页面每 2 秒检查新数据并更新所选权重、分布图和全权重表。权重统计的双端时间滑条按上方选定时区的固定 UTC 偏移筛选每天的对局开始时间，半小时步进，左闭右开，起点晚于终点时跨午夜；默认 00:00–24:00 保留原有全部样本。启用时间筛选后，没有可靠开始时间的样本不计入。时间段应用于所选权重和全权重表，保存在浏览器本地。全权重表每列表头可点击排序，再点切换升降序；切换筛选或更新数据时保留当前排序。

本工具不会主动下载全部官网 Replay；从最新对局开始逐页扫描，运行多久由开关控制。官网旧 Replay 可能过期；失败记录保留。再次扫描到同一 Session 且距离上次失败至少 1 小时后才重试。

“重复取样玩家”按 UID 汇总，排除非正数 UID 和结算名称为 `coop/Bot…` 的条目。可按全部（默认）、历史空战或历史陆战筛选，再选择最低出现场次（5/10/20/50/100/200/500/1000）和显示人数 N（默认 20）；点击任一列表头后，先对所有符合条件的玩家排序，再取前 N 人。列表显示取样场数、最常见组队权重和已记录对局的平均得分。点开后按历史空战/陆战与组队权重分别计算：K = 对空击杀 + 地面击杀，K/D = 总 K / 总死亡次数，K/R = 总 K / 有击杀数据的场数。平均得分只使用得分存在的场次；旧样本缺失战绩时仍计入取样场数，但不进入相应战绩比值。零死亡且有击杀时 K/D 显示 ∞。逐玩家样本已保存配置载具名称和内部代码。详情默认按模式及权重汇总，空战显示单一配置样本中最常见的载具；可切换成按空战载具型号拆分 K/D、K/R 和平均得分。陆战不按载具拆分整局战绩，配置阵容也不证明实际出击。这些统计直接读取 SQLite，不额外下载 Replay。原始样本仍保留 Replay 返回的 bot 条目，方便核查数据来源。

## 战局数据库与 CSV

单独导出的玩家 CSV 和 ZIP 内的玩家 CSV 均跳过非正数 UID 及结算名称以 `coop/Bot` 开头的 Bot 条目；不会误删名称中偶然含有 `bot` 的普通玩家。已保存的原始样本仍可用于页面核查和既有统计。

`data/battles.sqlite3` 的 `matches` 表每场只存一行：Session ID、开始时间、地图、模式、人数、结算段、对局权重区间，以及双方各自的权重区间和按非自动小队去重的平均组队权重。玩家击杀、得分、个人组队权重、国家和载具仍在 `data/wtstat_all.sqlite3` 的 `samples` 表。原数据库的 `replays` 表继续保存扫描状态；`samples` 中的模式和对局上限暂作现有统计查询的缓存。旧样本不会自动回填新战局库。

点击“导出战局＋玩家 CSV”会下载一个带 UTC 时间戳的 ZIP，内含同一时间戳的两份 CSV：战局每场一行，玩家每人每场一行且不重复写地图、时间、模式和双方权重。分享或迁移时解压后**先导入战局 CSV，再导入玩家 CSV**。按 Session ID 和 UID 去重。旧版合并 CSV 仍可通过“导入玩家 CSV”读取。“清除所有数据”会同时清空两个数据库中的采集数据。
